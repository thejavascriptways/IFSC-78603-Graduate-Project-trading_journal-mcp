Application Workflow Map

This screen explains how Trading Journal demonstrates the MCP concept. The browser UI and the console client use MCP through Python clients: the browser calls FastAPI, which hosts the internal client; the CLI connects directly to a selected MCP endpoint. Manual portfolio pages call services directly. MCP servers coordinate application services, the local database, audit logs, Alpaca for market snapshots, and Yahoo Finance for stock news. The Yahoo quote adapter remains optional.

Request Traces

Manual trade: direct service path
  1. Browser submits account, instrument, quantity, price, fees, and required reason.
  2. FastAPI validates the request; the portfolio service applies average-cost accounting.
  3. SQLite stores the trade and position changes; validation failures return an error.
  4. Request audit middleware records the outcome. Domain-level audit coverage is still being expanded.
Trades
Market data and news: internal MCP client path
  1. The page route builds the requested symbols and propagates a correlation ID.
  2. A Python MCP client initializes a session with the selected mounted server over Streamable HTTP.
  3. The server delegates to its service/provider; the external API supplies quotes or news.
  4. Structured results return to the page. Missing credentials, unsupported symbols, and provider errors remain visible.
  5. MCP operations are logged; Alpaca market-data requests and optional Yahoo quote requests also create external API audit records.

The internal HTTP client uses an in-process ASGI transport; it does not require a separate loopback network server.

MCP Console and CLI: discovery and invocation
  1. Select a registered server and initialize the session.
  2. Discover tools, resources, and prompts advertised by that server.
  3. Call a tool, read a resource, or render a prompt with validated arguments.
  4. Inspect structured output or an error. The browser host records the operation with a correlation ID.

Prompt rendering produces messages; it does not run an LLM or generate an investment decision.

Broker and trading: current implementation boundaries

Broker tools expose placeholder connectivity status. Order preview returns a preview only. Account synchronization, paper submission, and live order execution are future work.

Quote availability and freshness depend on provider coverage and feed entitlement. Yahoo Finance news is a demonstration integration. The Workflow Map describes architecture, not live health.

Browser Client Flow

Web UI Acting As An MCP Client

  1. 1
    User opens a page

    Example: Market Data, Stock News, MCP Console, or Dashboard.

  2. 2
    FastAPI route receives the request

    The web route prepares page data and starts an internal MCP client workflow when needed.

  3. 3
    Internal MCP client calls a server

    The app uses streamable HTTP MCP transport to call tools and read resources.

  4. 4
    MCP server delegates work

    The server calls the correct application service or provider adapter.

  5. 5
    Response returns to UI

    The page renders tables, cards, status notes, errors, and audit-friendly trace details.

Why This Is An MCP Use Case

Client And Server Separation

Multiple clients

The browser UI, MCP Console, command-line client, and future AI client can all use the same server capabilities.

Domain-specific servers

Each MCP server exposes focused tools/resources instead of mixing all features into one route.

Auditable tool calls

MCP calls can be logged, reviewed, and connected to user actions through correlation IDs.

Extensible providers

External data sources can change behind providers while MCP tools stay stable for clients.
